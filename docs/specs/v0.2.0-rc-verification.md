Part of [v0.2.0](v0.2.0.md). Labels: **Fact**, **Decision**, **Proposal**. No tag, Release or npm publish is part of this plan; v0.1.0 and v0.1.1 stay unchanged.

## RC verification (Proposal)

Run on the **packaged artifacts** from a `release.yml` dry run of the RC commit: Windows NSIS installed on a clean Windows user profile (or a fresh VM), and the Linux AppImage in a desktop session with a fresh home. Use real npm with a separate cache, synthetic projects, a synthetic Kubernetes API and fake credentials only. Record results as pass / fail / not-run per platform; nothing counts as verified on a platform where it was not run.

| # | Step | Windows NSIS | Linux AppImage | Check |
| --- | --- | --- | --- | --- |
| 1 | Packaging | ✓ | ✓ | Artifact names and SHA256SUMS match; notices and SBOM present |
| 2 | Install the app | ✓ | ✓ (chmod +x, run) | Installer warning for unsigned build documented; app starts |
| 3 | New user start | ✓ | ✓ | Onboarding shown, OS language chosen (en-US / ko-KR), no errors |
| 4 | Recommendation | ✓ | ✓ | `examples/demo-project` and a Kubernetes fixture: list, scores, verification line, diagnostics for an empty project |
| 5 | Client choice | ✓ | ✓ | Only selected clients written; verification levels shown; Cursor marked not verified |
| 6 | Project / User scope | ✓ | ✓ | Project default; User needs `user-scope-config`; other entries in user files kept |
| 7 | Install approval | ✓ | ✓ | Native dialog lists files and approval IDs; reject writes nothing; plan digest shown |
| 8 | Health | ✓ | ✓ | Real Health for memory-mcp (no credentials) and Kubernetes 0.0.67 (synthetic API): healthy |
| 9 | Update | ✓ | ✓ | Exact-version npx tool updated through the app (Prepare, Health, state commit) |
| 10 | Rollback | ✓ | ✓ | Back to the previous version, Health healthy, Version State consistent |
| 11 | Repair | ✓ | ✓ | Delete or edit the Kubernetes tool config → status drift → approved repair → Health |
| 12 | Language switch | ✓ | ✓ | en ↔ ko in the app; approval dialogs in the chosen language |
| 13 | Restart persistence | ✓ | ✓ | Language, INSTALLED entries and Version State kept after restart |
| 14 | Add to another client or scope | ✓ | ✓ | Already-used tool → add Codex project / Cursor user; same target is "no change" |
| 15 | Uninstall the app | ✓ | — | No user configuration removed by uninstall |

Exit criteria: every step passes on both Windows and Linux; no new CodeQL alert; `desktop-e2e`, `check`, `codeql`, `secret-scan` green on the RC commit; release notes state the Cursor and macOS limits and the Kubernetes version limit. A failure blocks the RC; a step that cannot be run is reported as not-run, not as passed.

## Remaining English gaps relevant to the RC (Fact)

- Approval dialogs (install, lifecycle, Adopt, Benchmark) are built from plan structure in English; no approval information is dropped.
- Pinokio: the Desktop only previews plans; approval and execution happen in the CLI, which is Korean-only. The Desktop preview shows Pinokio notices as `[code] Korean text` although the notices already carry codes (`venv-not-restored`, `manual-setup-required`, …). Proposal: English notice sentences by code.
- Manifest summaries are authored Korean text (display only). Release impact reasons show codes with levels. Recommendation reasons are generic per code, without names or numbers. None of these is shown in an approval dialog.
- Fixed in a separate PR: `TOOL_CONFIG_UNKNOWN` English meaning.
