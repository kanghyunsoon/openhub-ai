# Security model

OpenHub runs third-party tools on your machine, so it is built around a few fixed rules.

## Nothing runs without an approved plan

- Install, update, rollback, health check, adopt, benchmark and Pinokio runs all start from a plan that shows the exact executable, arguments, files to write, network use and required approvals.
- Approval happens in an interactive terminal or a native desktop dialog. There is no `--yes`, `-y` or `--approve` option. Non-interactive runs can only print the plan (`--json`).
- An approval is used once. The plan is rebuilt right before execution and must have the same digest.
- See [Approval model](approval-model.md).

## Execution boundaries

- Processes start with `shell: false` from an executable and an argument list. Manifest commands go through a strict tokenizer that rejects shell syntax.
- On Windows, npx-based servers are written to client configs as `cmd /d /c npx ...` with additional argument checks. OpenHub itself never runs `cmd`.
- Health checks and benchmarks start MCP servers in an isolated temporary directory with time limits, and terminate the whole process tree.
- Pinokio: only scripts generated by OpenHub from a fixed template are run, through pterm 0.0.25. Third-party Pinokio scripts are shown, never run.

## Files and secrets

- Project scanning is read-only and stays inside the project directory (symlinks and junctions that leave it are not followed).
- Config edits change only the target entry, keep unknown fields, write atomically and are reverted if a later step fails. `~/.claude.json` is never written.
- Environment variables are handled by name only. OpenHub does not read or check their values and never stores tokens, credentials or credential-bearing URLs in plans, results, logs, caches or Version State.
- Outputs do not contain absolute paths of your machine.

## Untrusted data

Release notes, repository descriptions, discovery candidates and AI summaries are untrusted text. They are shown as plain text, never executed and never used as approval. See [Discovery trust](discovery-trust.md) and [LLM privacy](llm-privacy.md).

## Scores are not security ratings

OpenScore reflects repository maintenance, activity and community signals; it is not a security or code-quality rating. About the Trending score: Not historical star growth: a deterministic score combining current popularity with recent release and repository activity. It does not rate security or code quality.

## Release integrity

Releases ship CycloneDX SBOMs and `SHA256SUMS`. The Windows installer is unsigned. See [Release process](release-process.md).
